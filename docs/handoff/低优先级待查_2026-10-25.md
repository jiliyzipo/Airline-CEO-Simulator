## 2. 为什么现在可以挂账

1. **三项都不是口径问题**。口径（线宽阈值、签名格式、状态三态）已经在代码与回归里钉死，
   人工只判「观感」，即使看不顺眼也只是调样式，不会改账、不会改判定。
2. **都不影响任何已通过的独立检测**。`REV-20261024132317-f6bf86` 的 `issues: []`
   覆盖的是 `unity-editmode` profile 的行为断言，与像素观感无关。
3. **补验成本极低但打断成本高**：需要开 Unity、造两条密度差航线、滚到新闻官那封邮件并截图，
   一次约 5–10 分钟；挂账不会随时间腐化（这三处样式在此之后没有改动计划）。

## 3. 补验时怎么做（照做即可，不必重新设计）

### P3-1 地图线宽

1. 开一局，确认至少有两条可执飞航线，且 `weeklyFlights` 一低一高（差 ≥ 3 倍）。
2. 打开地图页，同一缩放级别下截图。
3. 判定：**粗线明显比细线粗**（不是「能测出 0.4px」）。若两条看起来一样粗，记为观感未达标，
   再决定是把 2.0/2.4/3.0 拉开（例如 2.0/2.8/3.6）还是接受现状。
4. 顺带看一眼远端视角与拖动地图时线宽是否**保持屏幕像素**（不随缩放变粗）。

### P3-2 新闻官签名

1. 等一封外部来文（或读一个已有外部信的存档）。
2. 看列表发件人列：应为「新闻官 卢曦」而不是「中央气象台」。
3. 看详情：角色行「新闻官 · 预警通报」，落款「新闻官 卢曦」（**不得**出现「新闻官 ·  卢曦」双空格）。
4. 判定：截断/换行**不影响读出是谁**即可通过；若截断到只剩「新闻…」，记为需调列宽。

### P3-3 在途提示

1. 触发一封有延迟的信（运力呈报 2 小时 / 回执 4 小时），在它到达前打开收件箱。
2. 看列表头是否出现「在途 N 封（最近一封约 X 分钟后送达）」。
3. 判定：不遮挡第一封邮件的标题行、字号与列表正文一致即可。
