# S12-CommandConsole · 验收条款与证据对照（2026-10-25）

> 用途：`REV-20261025133501-b94646` 判定失败的根因是**条款与机器契约不一致**——
> 5 条验收条件全是手写业务条款，`unity-editmode` profile 的机器计数一条也证明不了，
> 检测者也没有显式补证，于是 5 条都是 `not_run`。
>
> 本次修订把条款拆成两层：
> - **AC1–AC3 恢复为 profile 的机器条款原文**（逐字一致，改一个字就会退回 `not_run`）；
> - **AC4–AC7 是业务条款**，机器不认，必须由检测者用 `--coverage` 显式声明。
>   下面给出每条的**可复跑证据**，检测者据以判断后再声明，而不是照抄。

## 一、机器条款（profile `unity-editmode` 自动认证，无需 `--coverage`）

| 条款 | 内容 | 机器证据 |
| --- | --- | --- |
| AC1 | 改动全部进入交付快照，导出后未列文件 0，清单与源指纹一致 | `stage-close` 的 export 阶段 |
| AC2 | EditMode 套件在隔离快照内真实执行，本 run 的 NUnit XML 全部通过 | `run-<token>/` 内的 NUnit XML |
| AC3 | 计数与机器结果一致：total>0、failed=0、skipped<total | 同上 XML 的 `test-run` 属性 |

这三条**不要**写进 `--coverage`。手写条款或改写措辞都会让 `machineCoverageFor`
判定为「自定义条款」，机器计数就无法证明它（这正是 SA03 的设计：宁可不认，也不编造通过）。

### AC4 · 四类写指令只经既有呈报管线

**证据用例**：`AirlineCEO.Tests.EditMode.WriteCommandTests.WriteCommands_RouteToExistingProposalPipelines`

| 断言 | 为什么这条能证明它 |
| --- | --- |
| 开线 → 收件箱出现 `action=open_route` 的呈报，且**尚未**建航线 | 命令台不自己建线，只把提案放进既有呈报管线 |
| 购机 → `action=buy_aircraft`，`aircraftType` 必须是最长匹配（`A320neo` 不得被 `A320` 截断） | 参数来自原话，且机型匹配不许前缀抢答 |
| 招聘 → `action=hr_recruit`，岗位/人数/渠道/紧急度与原话一致 | 同上 |
| 融资 → `action=finance_loan`，种类（租赁/银行贷款等）与原话一致 | 同上 |
| 同一句话连发两次只留一封呈报 | 去重，避免「说两遍批两遍」 |
| `汇报融资情况` / `招聘进度如何` / `贷款还剩多少` / `机队现在几架` → `needsRun=false` 且收件箱不增 | 读类句子不得被判成写指令（这是最容易回退的一处） |

### AC5 · 开航研究会纪要只有一个作者

**证据用例**：`AirlineCEO.Tests.EditMode.OpenRouteStudyTests.OpenRouteMemo_HasSingleSourceAndRejectsBeforeProfit`
（实现：`Assets/Scripts/Editor/OpenRouteStudyRegression.cs`，Console 打印一行「开航纪要单一出处」）

| 断言 | 为什么这条能证明它 |
| --- | --- |
| `Build(gs,"PEK","PKX",null)` → `ok=false`、`body` 为空、`rpm.score==0` | 否决发生在算引力模型/日利**之前**：被否决的机场对根本不会产出一封带日利的信 |
| 命令台说「开通北京首都—北京大兴航线」→ 只回理由，收件箱 0 新增 | 否决件不投递 |
| 同一机场对连调两次 → `subject`/`body`/`path`/`distanceKm` 逐字节相同 | 页面（`OpenRouteDecisionFlow.SubmitStudy`）与命令台（`DeptReportLogic`）都只调这一个函数，因此两者对同一机场对不可能给出两种说法 |
| `DistanceKm(PEK,JFK,null)` == `AirportGeoCatalog.GreatCircleKm`；经停 = 两段之和（必须真的大于直飞 15% 以上） | 直飞与经停不许各算一套距离 |
| 流程类上 `BuildStudyMailBody` / `FormatPath` 均不存在，`SubmitStudy` 仍在 | UI 侧不许再长出第二个正文作者；若有人加回来，纪要重新分叉 |

> 关于「两个作者」的说明：这条是结构断言，只能钉住已删除的两个函数名，钉不住「换个名字再加一个」。
> 真正堵住它的是复核时看 diff——但断言至少让「顺手把旧函数加回来」当场变红，而不是靠人记得。

### AC6 · 命令台历史可回溯

**证据用例**：`AirlineCEO.Tests.EditMode.CommandLogTests`
（`Record_…` / `Recall_…` / `Amend_…` / `Favorites_…` / `Ensure_…`，共 5 组 6 例）

| 断言 | 为什么这条能证明它 |
| --- | --- |
| `Record_` 新条目在前，仅相邻完全相同的两条合并 | 连发同一句不刷屏，但仍保留真实重复的历史位置 |
| `Recall_WalksBackwardsFromNewest_AndStopsAtTheEnd` | ↑ 从最新往回走，走到底停住（不会循环、不会回绕到最早再继续） |
| `Amend_RewritesTheMatchingEntry_WithoutAddingANewOne` | 确认/取消改写原条目而非追加新条目（历史不因「补个回执」而膨胀） |
| `Favorites_SurviveClearHistory_AndCapAtTwelve` | 收藏与历史是两套上限，清历史不清收藏 |
| `Ensure_IsIdempotent_AndDoesNotWipeExistingData` | 老存档加载不被清空 |

「点历史只填字并显示当时回执、不重放指令」属 UI 行为，EditMode 里只覆盖到数据层（`Recall` 返回条目与回执），
重放与否由 `CommandBarView` 的分支决定；**检测者可要求现场点一次确认**，本条声明以数据层为准。

### AC7 · 教程文案与常量同源

**证据用例**：`AirlineCEO.Tests.EditMode.TutorialCopyTests.TutorialCopy_MatchesRoutingAndConstants`

| 断言 | 为什么这条能证明它 |
| --- | --- |
| 教程 S6 给出的 5 个示例句逐条喂给 `CeoCommandRouter.Route` 都能落到对应主题 | 文案点名的句子真的能跑，不是「看起来像能跑」 |
| 启动资金文案里的金额 == `ActionExecutor.OpenRouteStartupCost` | 文案不另写字面量 |
| 首航结算金额 == `AdvisorTutorialScript.FirstFlightNetProfit`，董事会好感 == `FirstFlightBoardGain` | 结算与文案同一常量，改一处不会只剩一处 |
| 文案中不再出现「86 分 / 81% / 2.5 万 / 回本 8～10 个月」等未计算数字 | P23 的核心：不编造无法复现的数 |

## 三、检测者补证命令

```powershell
node tools/collab/cli.mjs stage-review --delivery <新 DEL> --actor codex `
  --coverage AC4=passed,AC5=passed,AC6=passed,AC7=passed
```

`--coverage` 只接受 `id=passed`；AC1–AC3 由机器认证，写不写都行。
若某条经复核不成立，**不要声明**，直接判失败并登记缺陷——`not_run` 是允许的结论，
「全部 passed」不是。
