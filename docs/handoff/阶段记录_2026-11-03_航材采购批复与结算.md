# 阶段记录 · 航材采购「批准无提示 · 到期不入库」（2026-11-03）

> 报障原文：「12月2日航材采购邮件，点批准后，下方没有提示。到17日，没有收到入库邮件。」
>
> 这是**两个独立缺陷**（一个 UI 算术、一个存档漏写），外加一条会掩盖前两者的兜底逻辑。

---

## 1. 缺陷一 · 点批准后提示条不显示（UI 算术）

`InboxPanelUI.LayoutReplyBox` 旧写法：

```csharp
float footer = bar ? 48f : 8f;              // bar = 批准/发起会议按钮是否可见
PlaceFooterNote(_hint, noteRight, footer);  // 下沿 8，上沿 footer - 4
```

- 批准成功后 `RefreshDecisionButtons()` 把「批准」按钮隐藏 → `bar = false` → `footer = 8`；
- 提示条自身下沿 `offsetMin.y = 8`、上沿 `offsetMax.y = footer - 4 = 4`；
- **上沿低于下沿，高度 = −4，TMP 什么都不画。**

讽刺之处：提示条最该出现的时刻，正好是「批复按钮刚消失」那一刻 ——
批准航材采购要告诉我们哪天扣款，批准时刻单要告诉我们何时交割，全都落进这一格。
而且这是全站性的：**任何**「批完就没有按钮」的邮件都读不到回执。

修法：抽出公开算术 `FooterHeight(hasDecisionBar, hasNote)`（48 / 40 / 8）与
`FooterNoteHeight(footer)`，有话说就留两行高度；没话说仍收回 8，不白占正文。

## 2. 缺陷二 · 机务状态从来没进存档（真正的「17日什么都没有」）

全仓搜 `MaintenanceSave`：只在 `Data/StrategyTypes.cs` 里定义，**没有任何读写点**；
`SaveManager` 连 `KeyMnt` 常量都没有，`AllSaveKeys` 里也没有 `ACEO_Mnt`。

后果链：

1. 12/2 机务部提案 `PN-ENG-001`，建单 `PO-001` 并发函 —— 函进了 `inbox`（存过档），**订单没存**；
2. 玩家存档/重开（或任何一次读档），`gs.mnt` 归零，订单表空；
3. 再点批准 → `ApprovePartsOrder` 按 `orderNo` 找不到订单 → 返回 false、`message = "未找到对应采购订单。"`；
4. UI 的兜底把**失败**当成「已办结」，`Mark(..., "approved")`，于是在列表里显示「已批准」；
5. 没有 `effectPending`，`SettleDueEffects` 永远不会为它排期 → 17 日无扣款、无回执。

修法三条：

| 位置 | 改动 |
|---|---|
| `SaveManager` | 新增 `KeyMnt = "ACEO_Mnt"`，登记进 `AllSaveKeys`，`Save()` 写 `MaintenanceSave`、`Load()` 读回（旧档缺键则建空态） |
| `InboxManager.QueuePartsMail` | 采购函把价量参数写进 `payloadCsv`：`数量\|单价\|交期\|加急\|供应商` |
| `InboxManager.ResolvePartsOrder` | 批准与到期结算共用：先按 `orderNo` 查；查不到就按函重建订单（旧档救命），两者皆空才返回 null |

## 3. 缺陷三 · 失败被兜底成「已批准」（撒谎）

`InboxPanelUI.Approve()` 里：处理器返回 false 且邮件仍 `IsOpen` 且 `!IsTransactionalMail` →
`Mark(approved)` + 「已批准。」。航材采购不在 `IsTransactionalAction` 名单里，于是被当成普通请示件结案。

修法：`IsTransactionalAction` 增加 `parts_order` —— 采购是「付钱换货」，
批准失败（订单丢失/现金不足）必须把原因留在提示条上、案子继续挂着，让 CEO 能拒绝或补条件。

## 4. 缺陷四 · 状态行不报具体日期

`InboxManager.StatusLine` 的「交割 / 落地」分支只写「第N年 QX」，
而航材采购、时刻交割都已改成按天排定 —— 玩家批准后看到「还在等交割」，却不知道钱哪天扣。

修法：`dueUtcTicks > 0` 时走 `DueCountdown`（`12月17日（还剩 15 天）`），旧档无绝对时刻才退回季度写法。

## 5. 附带：`MaintenanceManager.Instance` 的静默跳过

旧代码 `EnsureMaintenanceManager()` 是 `new GameObject + AddComponent`，但编辑器/批处理里
`Awake` 不跑，`Instance` 仍为 null，随后 `Instance != null && Instance.ConfirmOrder(...)` 直接短路，
玩家看到的就是「点了批准，什么也没发生」。新增 `MaintenanceManager.EnsureInstance()` 兜底赋值，
三处（批准紧急件 / 拒绝 / 到期结算）改用它。
