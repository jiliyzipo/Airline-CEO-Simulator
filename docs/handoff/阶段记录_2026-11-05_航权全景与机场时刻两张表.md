## 1. 改动清单

### 1.1 他航底表（新增 `Data/IndustryAirlines.cs`）

- 39 家航司：全球网络型 19 / 区域型 15 / 本地型 5；每条只记
  `name / code / hub / tier / region`。
- **只写「是谁、基地在哪、属于哪一档」，不写它持有哪些航权、占了多少时刻** ——
  那些人手写死就等于把「世界规模」和「名单」耦在一起，以后加一家航司要补一张全表。

### 1.2 推导与渲染（新增 `Logic/IndustryAirlineLogic.cs`）

- **确定性哈希**（FNV-1a，禁 `string.GetHashCode`）：同一存档、同一季度、同一机场，
  连查两次必得同一张表；换台机器、重启进程也不变。
- 航权：从基地出发的对外航点 = 第三/第四航权，全球网络型再补 1~2 条**第五航权**
  （他国 ↔ 他国，如 AF 的 BOS—TFU 段）。自由度一律交给
  `AirportRegions.FreedomOf` 判，**不另写一套**，免得表上写「第五航权」、
  提案信里写「第三/第四」。
- 航点**加权抽取**（不是均匀抽）：枢纽 6 / 干线 4 / 支线 1，同国再 +4。
  首版均匀抽会推出「英航 LHR—MFM（澳门）」「达美 DFW—SHA」这类分布，
  逻辑没错但不像航司网络 —— 现实里全球承运人的航点集中在枢纽与干线，
  支线只出现在本国做摆渡。
- 时刻：每个机场每个时段，他航按「档位 + 是否基地 + 是否同国 + 抖动」加权占槽，
  再逐个槽落到具体时刻（槽数可多于网格点，于是同一时刻会出现「×2」，
  正是现实里「同一时刻有多个系列」的写法）。
- 航权文案统一：`AirportRegions.FreedomLabel` 改用中文数字（第五航权），
  n77「已入账航权」卡删除自己那段 `第{freedom}航权` 拼接，改为调用同一函数 ——
  这张表上线后同屏出现「第三/第四航权」与「第5航权」两种写法，读起来像两个人写的。
- 我司那一组的「本国」取**基地机场所在国**（`AirportRegions.CountryOf(hub)`），
  不硬写「中国」：接管他国航司时（基地在巴黎），硬写会让整张表从第一行就错。

### 1.3 口径并轨（`Logic/RoutePermitLogic.cs`）

这是本轮**唯一会改玩法数字**的地方，必须写清楚：

```
池容量 = 我司持有 + 他航持有 + 可申请余量
```

- `SlotsAvailable` 改为「容量 − 我司 − 他航」。此前只扣我司，等于
  「池子里除了我司再没别人」——表上国航占了 3 条，游戏却让我司把 12 条全拿走。
- 他航占用量**永不把池子占满**（至少留 1 条）。所以这个改动只会让余量变小，
  不会把「开航缺槽」变成死结。
- 占用率 45%~80%（枢纽再 +5%），且必须服从 `容量 − 我司`：我司买得多了，他航让位。
- `SlotPoolLine` / `SlotPoolLineAt` 同步改口径：`池 7/12（我司 2 · 他航 5 · 余 5）`。
  邮件里的「余 N」与表上那几个「—」从此是同一个数。

### 1.4 界面（`UI/StrategySubpagePanel.cs`）

- n77 二级标签从 2 个扩到 4 个（标签宽 0.125、字号 12）：
  **持仓与在办 / 时刻二级市场 / 航权全景 / 机场时刻**。
- 「航权全景」：我司在最前（**真实持仓**，与「已入账航权」卡同源），其后按档位列他航；
  表头写明「他航为行业口径」，并注明同一对航点可由多家承运人同时持有。
- 「机场时刻」：协调机场全列（80 个），排序 = 我司有持仓 → 枢纽 → 干线 → 代码。
  每个机场一行池况 + 四个时段；每个时段一行
  `06:30 国航｜07:00 —｜07:30 东航×2`，**空闲位只写「—」，不写任何航司名**。
  支线机场非协调、不占池，末尾一句带过，不塞进表里充数。

### 4.6 首轮实跑抓到的一个真问题（不是断言写错）

`t043` EditMode 首跑 136/137，R48 报出 22 个时段「空闲方块数 ≠ 可申请余量」：

```
R48 PEK 中：空闲方块 0 个 ≠ 可申请余量 6 条。
R48 PKX 夜：空闲方块 6 个 ≠ 可申请余量 3 条。
```

根因不在断言，在 `SlotHolders` 的**落位方式**：首版按 `k % grid.Count` 顺序填槽，
容量 14 的时段把前 8 个时刻全占满、后 6 条槽无处分摊。界面上表现为
**整段每块都有航司、旁边却写着「余 6」** —— 正是 CEO 最不能接受的自相矛盾。

修法（`IndustryAirlineLogic.ChipsOf`）：
- 占用 `occupied ≤ 网格数` 时按 `k * grid / occupied` **均匀散开**，空位彼此隔开；
- `occupied > 网格数` 时仍 `k % grid`，每个时刻自然有 1–2 家（正常现象，显示「×2」）。

顺带补出第三态 `vacant`：池容量小于时段时刻点数（干线夜班 4 槽 / 7 个时刻）时，
会出现「该刻无人持有、但本段已排满」的块。它不能标绿（段里一条余量都没有，
标绿就是骗人），也不能留白（会被读成渲染漏了），故画成灰「—」。

断言随之从「绿块数 == 余量」（本身就错：绿块是**整刻**空着，余量是**段级**）改为四条：
① 每个网格时刻都有方块；② Σ 系列数 == 已占用槽数；③ 绿块只在余量 > 0 时出现；
④ 有余量且占用 < 时刻数时必须真的有绿块（挡住「槽被挤在开头」这个回归）。
