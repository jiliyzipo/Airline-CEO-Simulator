# T03.8 · 实际 UI 走查清单

日期 2026-10-18。T03 只剩这一项：从**真实 UI** 走通邮件关键词 → 详情返回 → 批复 → 执行回执，并核对列表／详情／地图／邮件里的航线与数字。

代码层证据已经齐了（PlayMode 99/99、EditMode 25/25），缺的是**肉眼与鼠标**这一层。以下是照着点就行的一条路径，以及每一处"应该看到什么"。

---

## 0. 准备

1. 用 `6000.3.21f1` 打开 `Unity Project`，打开场景 `Assets/MVP V1.0.unity`（不是 `SampleScene`）。
2. Play → 主菜单。入口有三个：`新游戏 · 接管`、`从零创建`、`继续 / 读档`。
   **建议选 `新游戏 · 接管`，存档名用 `T03UI`**，别覆盖你正在玩的档。
3. 开局先记下四样东西（后面全程拿它对）：

   ```text
   航司名：            现金：          
   日历：第 __ 年 Q__   收件箱未读数：___
   ```

4. 时钟先 1×，需要赶时间再切 3×。**Play 期间时间真的在走**，手别离开，免得错过一笔回执。

---

## 1. 邮件关键词（4 类链接都要点到）

打开收件箱（`n7 收件箱`），挑一封正文带关键词的邮件。点正文里**带下划线/高亮**的词，看它跳到哪：

| 点这个词 | 应打开 | 落点校验 |
| --- | --- | --- |
| `航权与时刻槽` / `时刻槽` | `n77 航权与时刻槽` | 页面标题对，且不是空白页 |
| `航班详细计划` / `航班计划` | `n43 航班详细计划` | 同上 |
| `RPM 评估` / `RPM` | `n35 新航线·RPM 评估页` | 同上 |
| `PEK-SHA` 这类三字码对 | 对应航线/城市页 | 目的地、城市名与三字码一致 |

再看邮件底部的按钮行（不同邮件按钮不同）：

| 按钮 | 应打开 | 落点校验 |
| --- | --- | --- |
| `详见 · 本航线` | `n41 单航线` | 打开的航线**就是这封信说的那条**（三字码一致） |
| `详见 · 机队` | `n9 机队` | — |
| `详见 · 航权与时刻槽` | `n77` | — |
| `详见 · 航线网络` | `n12 航线网络` | 停在对应城市，不是报告里的 routeId |

**返回**：每进一个页面后，用页内返回／导航返回退回，确认**回到原来那封邮件**、列表选中项没跳、滚动位置没回到顶部。这一条单独记一次结论。

> 已知易错点：`n12` 的键是城市三字码。若在 `n12` 里看到 `PEK-SHA` 这种整串当城市名，就是串键了。

---

## 2. 批复

找一封**待批**邮件（底部有 `批准` 按钮的那封）：

1. 点前记：现金、该航线是否已存在、按钮文字。
2. 点 `批准`：
   - 按钮应消失或变成已批准状态；
   - 现金**只按规则动一次**（开航才扣启动资金的，此时不应扣）；
   - 邮件底栏出现「已批准」类文案。
3. **幂等**：如果按钮还能点，再点一次；如果已消失，切到别的邮件再切回来。不得出现第二次扣款、第二条重复申请、或旧呈报重新生效。
4. **串信检查**：切到另一封邮件，底栏不得残留上一封的「已批准…」字样（这是以前报过的缺陷）。

---

## 3. 回执（延迟投递）

批完**不要**立刻去收件箱找结论——回执是延后投递的。

1. 让时钟走一格（或推进到下一季）。
2. 收件箱应出现一封**回执/汇报件**：
   - 内容里的航线、班次、时刻与批准那封**同源**；
   - 这封信**不应有 `批准` 按钮**（汇报件无需决策）。
3. 若时钟推进后迟迟没有回执，或回执出现在"当前季"却写着别的季度的数据，记缺陷。

---

## 4. 执行回执（真起飞 → 真落地）

1. 把时钟放到计划离港前几分钟（看 `n43` 的时刻窗口）。
2. 到点后看运营页：该班应显示**执飞中**，机号是实际分配的那架。
3. 落地后看执行记录：机号、起降时刻、航线与计划一致；槽使用与收益不出现两套数。
4. **反例**（如果这局有停飞/无机航线）：列表里该线显示 `⚠ 停飞不计营收`，地图/日历上**不应**还有这班的舱位或航班；也不应产生"幽灵收入"。

---

## 5. 数字对照表（逐行填，别只写"一致"）

同一条航线，把四个地方的数字抄下来：

| 项目 | 列表 `RouteCard` | 详情 `n41` | 地图 | 邮件 |
| --- | --- | --- | --- | --- |
| 三字码 |  |  |  |  |
| 每周班次 | `N 班/周` | 班次行 `N 班/周` | 线宽（越粗越密） |  |
| 利润 | `日利 X.X 万` | `WEEKLY PROFIT X.X 万` | — | `预估日利润 X 万美元` |
| 开航 | `第 N 年 QX 开航` | — | — | — |
| 需求 | `周需 商务/超经/经济` | — | — | — |

**口径先对齐再判断，否则会把正确当错误：**

- 列表 `日利` 是**航线级日净利** = Σ各班日毛利 − 航线日固定成本。
- 详情 `WEEKLY PROFIT` 是**单班**的 `日毛利 × 该班周班次`，不含航线固定成本。
- 所以 `列表日利 × 7` 与 `详情周三` 本来就不相等，差的就是固定成本。**判定标准**：同一口径内自洽、单位一致（都是"万美元"）、班次与开航时间跨页面相同。
- 地图没有数字，只表达疏密。线宽顺序应与班次顺序一致（粗 = 班次多）。
