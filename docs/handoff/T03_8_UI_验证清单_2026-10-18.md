# T03.8 · 实际 UI 走查清单

日期 2026-10-18。T03 只剩这一项：从**真实 UI** 走通邮件关键词 → 详情返回 → 批复 → 执行回执，并核对列表／详情／地图／邮件里的航线与数字。

代码层证据已经齐了（PlayMode 99/99、EditMode 25/25），缺的是**肉眼与鼠标**这一层。以下是照着点就行的一条路径，以及每一处"应该看到什么"。

## 0. 准备

1. 用 `6000.3.21f1` 打开 `Unity Project`，打开场景 `Assets/MVP V1.0.unity`（不是 `SampleScene`）。
2. Play → 主菜单。入口有三个：`新游戏 · 接管`、`从零创建`、`继续 / 读档`。
   **建议选 `新游戏 · 接管`，存档名用 `T03UI`**，别覆盖你正在玩的档。
3. 开局先记下四样东西（后面全程拿它对）：

   ```text
   航司名：            现金：          
   日历：第 __ 年 Q__   收件箱未读数：___
   ```

4. 时钟先 1×，需要赶时间再切 3×。**Play 期间时间真的在走**，手别离开，免得错过一笔回执。

## 2. 批复

找一封**待批**邮件（底部有 `批准` 按钮的那封）：

1. 点前记：现金、该航线是否已存在、按钮文字。
2. 点 `批准`：
   - 按钮应消失或变成已批准状态；
   - 现金**只按规则动一次**（开航才扣启动资金的，此时不应扣）；
   - 邮件底栏出现「已批准」类文案。
3. **幂等**：如果按钮还能点，再点一次；如果已消失，切到别的邮件再切回来。不得出现第二次扣款、第二条重复申请、或旧呈报重新生效。
4. **串信检查**：切到另一封邮件，底栏不得残留上一封的「已批准…」字样（这是以前报过的缺陷）。

---

## 3. 回执（延迟投递）

批完**不要**立刻去收件箱找结论——回执是延后投递的。

1. 让时钟走一格（或推进到下一季）。
2. 收件箱应出现一封**回执/汇报件**：
   - 内容里的航线、班次、时刻与批准那封**同源**；
   - 这封信**不应有 `批准` 按钮**（汇报件无需决策）。
3. 若时钟推进后迟迟没有回执，或回执出现在"当前季"却写着别的季度的数据，记缺陷。

---

## 4. 执行回执（真起飞 → 真落地）

> **2026-10-19 实跑更正**：本节原文写的「运营页」「执行记录页」**在现界面不存在**。
> 底部导航只有 主页/收件箱/航线/机队/人员/维护/财务/培训/愿景；运营部内容已并入「航线」模块。
> 全工程无 `FlightLog`/执行记录页，逐班历史没有落库到 UI —— 执行痕迹只有两处：
> ① 机队页每架飞机的**状态**（适航 / 飞行中）；② 飞机详情·履历的**累计 FH / FC**。

1. 把时钟放到计划离港前几分钟（看 `n43` 的时刻窗口）。
2. 到点后在 **机队**页看该机状态：`适航` → `飞行中`，机号是实际分配的那架（已验通过）。
3. 落地后：状态回到 `适航`；进「飞机详情·履历」看 `累计 X FH / Y FC`，**Y 应恰好 +1**（一班一次循环），
   X 增加约一个轮挡小时。若 Y 一次 +2 或飞了但 Y 不动，即为重复结算/漏结算。
4. **反例**（如果这局有停飞/无机航线）：列表里该线显示 `⚠ 停飞不计营收`，地图/日历上**不应**还有这班的舱位或航班；也不应产生"幽灵收入"。

## 5. 数字对照表（逐行填，别只写"一致"）

同一条航线，把四个地方的数字抄下来：

| 项目 | 列表 `RouteCard` | 详情 `n41` | 地图 | 邮件 |
| --- | --- | --- | --- | --- |
| 三字码 |  |  |  |  |
| 每周班次 | `N 班/周` | 班次行 `N 班/周` | 线宽档（见下） |  |
| 利润 | `日利 X.X 万` | `WEEKLY PROFIT X.X 万`（另单列顶部`周利`） | — | `预估日利润 X 万美元` |
| 开航 | `第 N 年 QX 开航` | — | — | — |
| 需求 | `周需 商务/超经/经济` | — | — | — |

**口径先对齐再判断，否则会把正确当错误：**

- 列表 `日利` 是**航线级日净利** = Σ各班日毛利 − 航线日固定成本。
- 详情 `WEEKLY PROFIT` 是**单班**的 `日毛利 × 该班周班次`，不含航线固定成本。
- 详情顶部 `周利` = `dailyProfit × 7`（航线级）—— 与上面那个**本来就不相等**，两个都要分别填。
- 所以 `列表日利 × 7` 与 `详情周三` 本来就不相等，差的就是固定成本。**判定标准**：同一口径内自洽、单位一致（都是"万美元"）、班次与开航时间跨页面相同。
- **地图线宽（2026-10-25 修订）**：`MapWidget.RouteThickness` 已按周离港班次分档 ——
  ≤7 班 → 2.0 px、8–20 班 → 2.4 px、>20 班 → 3.0 px。
  判据改为"线宽档位与班次档位一致"，且应拿**差距最大的两条**（一条 ≤7 班 vs 一条 >20 班）对比；
  相邻档（2.4 vs 3.0）在地图缩放下肉眼难分，不算缺陷。
  > 旧版此处写"地图不表达班次（当前实现恒宽）"是 2026-10-19 的现状，已被 T03.8 代码改动作废。

## 走查中登记的缺陷与修复（2026-10-19）

| # | 报障原话 | 根因 | 修复 |
| --- | --- | --- | --- |
| D1 | 「航班号没有关键词设置」 | `TermNavMap` 只包机号/三字码对，未收录航班号 | 新增 `flight:` 链接 → `n43`；按航线现算整块预留号段；边界只认 ASCII 词字符（`char.IsLetterOrDigit` 会把汉字当字母，`执飞NS148。` 会漏包） |
| D2 | 「收到新邮件，右侧正文跳到顶端」 | `OnInboxChanged → RenderDetail → RefreshBodyScroll` 无条件置 `verticalNormalizedPosition = 1` | 按邮件 id 判定：同信重绘保留位置，换信才回顶；布局类调用统一 `preservePosition: true` |
| D3 | 单航线页关键字跳转落到「上一次选中的航线」 | `RouteDetailPanel.OnKeyword` 只处理 `n10`，不写回 `routeKey` | 按 `hit.pageId` 写回 `FleetNetContext.SelectedRouteId` / `OpsSubpageContext.SelectedRouteId` |
| D4 | 「CEO 下达指令后，邮箱立即收到汇报，应该过几小时才把呈报送到收件箱」 | `QueueCapacityReport` 直接 `Add`，指令敲完呈报即入箱；`QueueSlotApplications` 派生的时刻槽单也是 `Add` | 新增 `InboxCadence.ReportHours = 2`；`QueueCapacityReport` / `QueueApplySlots` / `QueueChangeSlot` 统一走 `Enqueue(gs, mail, delayHours)` 延后投递（3× 下约 40 秒）；同时清掉待发队列里同航线的旧呈报，`Schedule` 重排时更新 `deliverUtcTicks` |

**未覆盖**：`航班详细计划` 词条在本档无对应邮件（仅排班呈报正文含此词，而该档 8 条航线均已生效），
