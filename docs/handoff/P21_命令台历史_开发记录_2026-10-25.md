## 1. 做了什么

| 能力 | 入口 | 行为 |
|---|---|---|
| 历史指令 | 命令条右侧「历史」按钮；输入框内 ↑ / ↓ | 最近 60 条倒序列出；↑ 往更早、↓ 往回，退到头还原翻之前自己写的那半句 |
| 回执回溯 | 历史列表点任意一条 | **只把原话填回输入框，并重显当时的回执**；绝不重新执行 |
| 指令收藏 | 每行 ☆ / ★ | 独立列表（上限 12），最新在最前，超限淘汰最旧；清历史不连坐 |

## 2. 为什么这样设计（三条边界）

1. **历史不参与任何判定**。`commandLog` 只被命令台 UI 读写，路由、台账、账务、季结一律不看它。
   把 `commandLog` 整个清空，游戏行为一字不变 —— 这是「体验数据」与「游戏状态」的分界。
2. **召回只填字，不执行**。写指令（关线）重放一次就是事故。点历史 = 看，不等于下。
   与「↑ 回车」的区别是：↑ 只是把字填进去，仍要玩家自己按回车，确认卡照旧会弹。
3. **收藏与历史分家**。历史有 60 条上限，收藏必须活得比历史久；若把 favorite 挂在 entry 上，
   清一次历史收藏全丢。所以是两份数据：`commandLog` + `commandFavorites`。

## 3. 写指令的那条特殊处理

关线是唯一「先弹确认卡、之后才执行」的路径。若执行时才追加一条新历史，
同一句话会在列表里出现两次，看起来像「下过两遍令」。所以：

- 弹卡时先记一条 `已弹确认卡（尚未执行）`；
- 点「确认停飞」/「取消」后，用 `CommandLog.Amend` **改写那条**为真实结果（`已执行｜…` / `未执行｜…` / `已取消（未执行，台账未动）`）；
- 找不到匹配（例如历史被清过）返回 false 静默放行 —— 历史是体验数据，不该挡住执行。
