# P26 交接单与检测命令一致性 · 开发记录（2026-10-27）

阶段：`S16-CollabFidelity`
范围：`tools/collab`
起因：`DEL-20261026134228-f7662c` 的检测在 `collab` 163 项全通过的情况下判为失败（`REV-20261026134946-742612`），原因是交接单要求补证、却给了一条不带补证的命令。

## 一、四处「说的和做的不一致」

### 1. 交接单给的检测命令必然失败（AC4）

`renderHandoff` 顶部警告「AC2–AC6 需显式补证」，底部「检测命令（Codex 一条命令）」却是裸的 `stage-review --delivery X --actor codex`。照着执行就得到 `not_run`。

现在未映射条款会按同一份 `machineCoverage` 生成 `--coverage`：

```powershell
node tools/collab/cli.mjs stage-review --delivery DEL-x --actor codex --coverage "AC3=passed,AC4=passed"
```

命令与警告出自同一个集合，不可能再分叉。`stage-close` 打印并复制到剪贴板的那条同样带参数。

### 2. 明知不可能通过仍跑满套件（AC5）

新增 `assertReviewable`：在授权之后、加锁与 `review-start` 之前，用 `machineCoverageFor(task, profile, null)` 算出「一次运行之下也证明不了」的条款；若这些条款没有在 `--coverage` 里出现，直接：

```
EXIT.USAGE(2)   stage-review would fail by construction: AC2, AC3 ... Nothing was run.
extra: { needsAttestation: [...], suggestedCoverage: '--coverage "AC1=passed,..."' }
```

不建 review、不登记 issue、不动 revision。只有 `skipped>0` 这种「跑完才知道」的降级仍走原先的事后判定。

### 3. 终态缺陷仍挂在待办里（AC6）

`generateSummaries` 原来只排除 `closed`，于是 `wontfix`/`verified` 依旧出现在 `CURRENT.md` 与 `NEXT_CODEX.md`。现在统一白名单 `open|fixing|fixed`。缺陷报告文件本身不可变（`listIssues` 的设计），只是不再被当作待办。

实机验证：`ISSUE-20261026121935-4e76e6`、`ISSUE-20261026135154-c11728` 已从两份文件消失，三条 `fixed` 仍在。

### 4. 改写模板条款被静默降级（AC7）

把 profile 模板的 AC 改一句措辞，它就从「机器可判定」掉成「需人工担保」——这正是 S15 发生的事，当时我以为是措辞问题。

新增 `lib/clauses.mjs`，把模板与漂移判定从 `stage.mjs` 拆出来（`task-add` 需要它，而 `stage.mjs` 已经 import `commands.mjs`，直接互相 import 会成环）：

- `clauseDrift(cfg, task, profile)`：给定 profile（`stage-close`）→ 与该 profile 模板逐字比对；
- 不给 profile（`task-add`，此时尚未选 profile）→ 只报「某个 profile 在该编号有模板、但文本一个都不匹配」的条款。逐字照抄任一模板的条款不算降级，避免四条模板互相干扰产生噪音。

告警示例：

```
⚠ S16-CollabFidelity：AC4 与 profile 模板文本不一致，已由「机器可判定」降级为「需检测者人工补证」（collab(AC4)）。
```
