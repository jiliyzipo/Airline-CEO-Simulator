## 1. 部门预算的季末分摊（矩阵 §6.4）

### 1.1 现状（代码事实）

`TimeManager.AdvanceQuarterCore` 第 196 行：

```csharp
float deptQuarterExpense = (gs.monthlyBurnRate + gs.FleetMonthlyMaintenance
                          + gs.FleetMonthlyLease  + gs.CeoMonthlyPayWan) * 3f;
FinanceManager.AccrueBudgetSpend(gs, deptQuarterExpense);
```

三个直接后果：

| # | 后果 | 触发条件 |
|---|---|---|
| 1 | 用**季末当时费率 ×3** 反推整季，中途加机／退租／改预算的人，前 45 天被按新费率重算 | 任何季内机队或费率变动 |
| 2 | 分母不含运行人员薪资（`OperationalPayrollMonthlyWan`）与存量人力（`LaborCostMonthlyWan`），而 `liveQuarterExpense` 含 | 一贯 |
| 3 | 不含过渡业务（收入与违约金都不进），也不含 irrops／排检等一次性支出 | 有过渡合同或异常 |

于是「部门预算执行率」与「季度实际支出」在结构上就不可能相等，只能靠文案解释。

### 1.2 三个方案

| 方案 | 做法 | 改动面 | 优点 | 代价 |
|---|---|---|---|---|
| **A1 只写进报告** | 代码不动，在财务页与季报上明确标「部门预算是问责口径，非现金账」 | 0 行代码 | 零风险 | 玩家看到的两个数仍然对不上，且中途变更时**连问责本身也不公平**（按季末费率算前 45 天） |
| **A2 逐日累计同口径** | `GameState` 新增 `liveQuarterDeptExpense`；日推进扣日固定时同步累加**当日**的「部门可管固定成本」；季末用它替换公式 | 新增 1 字段（默认 0）+ 1 处累加 + 1 处替换 + 迁移（老档该字段为 0 → 季末退化为 0 分摊，需处理） | 中途变更自动切片；跨季不重复；与现金同日同费率 | 新增存档字段；老档首季需要退化策略 |
| **A3 直接用 `liveQuarterExpense`** | 季末把 `liveQuarterExpense` 当问责分母 | 1 行 | 两把尺子合成一把，永远相等 | 工资（含继承机组）与过渡违约金也摊进部门预算，而预算条目里**没有工资项** → 运营／人力部每季必「超支」，问责信号被噪音淹没 |

### 1.3 推荐：A2（限定「部门可管」口径）

理由：问责的对象应该是**部门能决定的钱**。工资由编制和人头决定（人力部有独立看板），
过渡业务是市场行为（不进部门预算），违约金是合同罚则 —— 三者都不该按 8 部门额度摊销。
而「烧钱率 + 机队维护 + 租赁 + CEO 薪酬」恰好是现有公式已经选定的那四项，只是**取数时点错了**。

具体形态：

```csharp
// 日推进扣日固定时同步累加（与 LiveClockLogic.DailyFixedCostWan 同源，但只取部门四项）
gs.liveQuarterDeptExpense += (gs.monthlyBurnRate
                            + gs.FleetMonthlyMaintenance
                            + gs.FleetMonthlyLease
                            + gs.CeoMonthlyPayWan) / 30f;

// 季末
FinanceManager.AccrueBudgetSpend(gs, gs.liveQuarterDeptExpense);
gs.liveQuarterDeptExpense = 0f;
```

老档迁移：字段缺失即 0，季末 `AccrueBudgetSpend` 收到 0 会直接 return（现有守卫 `quarterExpenseWan <= 0f`），
**结果与「不计入」一致**而不是「记错」；可在读档时若字段为 0 且 `simDay > 1` 时按 A1 文案提示一次。
如果希望老档首季也能分摊，退化为「当前费率 × 已过天数 / 30」，但这等于又引回 1.1 的第 1 条缺陷 ——
**推荐不退化**，老档首季如实少一次问责，比记错一次更好。

### 1.4 验收标准（若采纳 A2）

1. `DevelopmentAccountingScenarioTests.S8` 增断言：中途加机后，`AccrueBudgetSpend` 收到的分母
   落在 `preDays × daily_pre + postDays × daily_post` 的 ±0.05 万内（现在的用例只对账现金与季度桶）。
2. 新增 EditMode 用例：同一季内改 `monthlyBurnRate` 两次，分母按各段实际天数加权。
3. 基线读数必须逐位不变（`closing/net/runway`）—— 部门预算不进现金与跑道，改了也不该动。

### 1.5 结论

**推荐 A2；若裁定「不改」，则按 A1 写入 T04 报告与财务页文案，并保留 §6.4 的 `?` 标记。**

## 2. 召回违约金是否进过渡业务季度桶（矩阵 §6.2）

### 2.1 现状（代码事实）

`TransitionBusinessLogic.OnDayTick` 第 945–951 行：交机当日

```csharp
gs.cash -= c.recallFeeWan;
gs.yearNetProfit -= c.recallFeeWan;
// 不进 liveQuarterTransitionIncome，也不进 liveQuarterExpense
```

`Recall` 时（第 867–868 行）只算金额、发公函，不动账。

三个后果：

| # | 后果 |
|---|---|
| 1 | 「Δ现金 == Σ应计桶」这条恒等式在召回当期**不成立** —— 现金少了，但没有任何桶记录这笔支出 |
| 2 | 季报「过渡业务本季入账」只报收入不报违约金，读者会以为这单赚了 |
| 3 | 年度利润扣了、现金扣了，唯独季度桶没扣 → 跨季对账时这笔钱「凭空消失」 |

### 2.2 三个方案

| 方案 | 做法 | 语义 | 代价 |
|---|---|---|---|
| **B1 维持不进桶** | 现状；季报另加一行「违约金 −Y」纯展示 | 违约金是「营业外损益」，不入业务桶 | 恒等式永久留一个例外；任何以后写的对账用例都得记住这条特例 |
| **B2 记入 `liveQuarterExpense`** | `gs.liveQuarterExpense += c.recallFeeWan` | 违约金是**支出**，进支出桶 | 与日固定混在一起，季报要么拆行、要么说「含违约金」 |
| **B3 新增 `liveQuarterTransitionFee` 独立桶** | 新字段 + 迁移 + 所有断言更新 | 最干净：过渡业务有「收入 / 罚则」两栏 | 新增存档字段、季末要清、`GameState` 字段面继续膨胀 |

### 2.3 推荐：B2

关键论点：**违约金是现金流出，恒等式必须闭合**。B1 让 `AssertCashEqualsBuckets` 在召回当期失效，
这条断言正是矩阵 §4 的核心；留一个口头例外，等于把「机器能证明的」降级成「人记得住的」。
B3 更漂亮，但它换来的只是季报里少一次拆分，而代价是又加一个要迁移、要清零、要逐处断言的字段。

B2 的附带收益：`DevelopmentAccountingScenarioTests.S6` 结尾可以把
`AssertCashEqualsBuckets` 一路断言到交机完成（现在故意停在前一天），召回这条路径也进入恒等式保护。

### 2.4 验收标准（若采纳 B2）

1. `S6` 在召回交机后补 `AssertCashEqualsBuckets`（现在缺，因为会失败）。
2. 断言 `liveQuarterExpense` 增量 == 通知期日固定 + 违约金。
3. 季报文案：「过渡业务本季入账 X 万（另付违约金 Y 万）」—— Y 从 `liveQuarterExpense` 里取不到，
   需在 `TransitionContract` 或季报快照里留一个 `recallFeePaidWan` 字段用于展示（只用于文案，不进计算）。
4. 基线读数逐位不变（违约金只在有召回时发生，seed 42 年跑无召回）。

### 2.5 结论

**推荐 B2；若裁定「维持 B1」，则在 T04 报告里把恒等式写成「除召回违约金外」，并把 §6.2 的 `?` 保留。**

## 3. 两条的共同点（供裁定时一并考虑）

1. **都不影响现金与跑道**：一个只改分摊键，一个只在有召回时改桶。`closing / net / runway` 应当逐位不变，
   这是判断「改动是否越界」的硬指标。
2. **都能被现有用例抓住**：A2 抓在 S8，B2 抓在 S6 —— 两条裁定落地后都有现成的红/绿信号，不需要新造场景。
3. **都建议「最小语义改动」**：A2 沿用现成的四项、B2 沿用现成的支出桶。真正需要新字段的方案（A3 / B3）
   都是「更整齐但收益不足」，留给以后有更多业务桶时再重构。
