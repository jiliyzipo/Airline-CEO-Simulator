## 四、修复路径（同交付复检，不新增 DEL）

`REV-...f02d73` 终态不可撤销，`--force` 是 `cmdStageReview` 中唯一跳过「已有终态记录即返回旧结论」的开关。

```

```

两条都必须由 Codex 或用户执行：`wontfix` 不在 Cursor 的 `ISSUE_ROLE_STATUS` 内，`stage-review --actor codex` 也不得由 Cursor 执行。

### PowerShell 引号要求

`--coverage` 的值必须加引号。PowerShell 在调用原生程序时会把未加引号的 `a,b,c` 拆成多个参数，`parseArgs` 只取紧跟 `--coverage` 的那一个，剩下的会落进 `_`（被忽略），结果只有 AC1 被补证、AC2–AC4 仍为 `not_run`，从而再次判负。

## 五、暴露的工具缺陷（下一阶段验收条件候选）

### D3 · `stage-review` 静默忽略未知参数

`parseArgs` 对任何 `--xxx` 都照单全收，命令侧也不校验自己认识哪些参数。后果分两层：

1. `--dry-run` 这种「听起来只读」的参数在 `stage-review` 上不具备只读语义，却没有任何提示——最容易误触的形态；
2. 拼错的参数（例如 `--coverge`）会被静默丢弃，命令照常执行，用户以为生效了。

建议验收条件方向：命令级参数白名单 + 未知参数直接 `EXIT.USAGE`；`--dry-run` 要么在 `stage-review` 上实现为真正的只读预演（解析交付、profile、机器覆盖、待补证清单，不落任何记录），要么明确拒绝。证据：collab 子套件中「未知参数被拒」与「stage-review --dry-run 不产生任何 REV/ISSUE/revision 变化」两条用例。
