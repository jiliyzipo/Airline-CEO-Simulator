# P32 · T04.8 遗留数值疑点：低成本为何比支线还差（单因子对照实验）· 开发记录（2026-10-27）

## 1. 要回答的问题

`docs/handoff/残余七项审计_2026-10-24.md` §8.5 / `tools/balance/README.md` §压测口径 第 5 条
挂着 60 组合矩阵里唯一剩下的数值疑点：

> 低成本在滞胀/衰退下（净利 −1122 / −504）比支线（−805 / −457）**还差**。
> 定案前需要一次对照实验：单独调 `yieldMultiplier` 0.85→0.90、再单独调
> `CompetitorSupply` 回 0.55，看哪个是主因。

原话还写死了纪律：**在没做这个对照前，不得宣称这条已「验证」。** 本节就是把这个对照做掉。

## 2. 实验设计：一次只动一个旋钮

新增 `dotnet run --project tools/balance -- --ablate`（`tools/balance/Stress/RouteAblation.cs`）。

固定项：标准难度（期初 500 万）、seed 42、一个财年、6 月一次 IRROPS、只跑压力情景
（衰退 / 油价冲击 / 滞胀）—— 繁荣期三家都赚，看不出归因。

变体（都基于低成本航司的机队与航线）：

| Key | 改动 | 为什么要有这一行 |
|---|---|---|
| `lcc_base` | — | 基准 |
| `lcc_yield` | `yieldMultiplier` 0.85 → 0.90 | 审计点名的第 ① 个候选 |
| `lcc_supply` | `CompetitorSupply` −0.10 | 审计点名的第 ② 个候选 |
| `lcc_both` | 两者同调 | 看交互项大不大 |
| `lcc_yield_to_1` | `yieldMultiplier` → 1.00（拉平支线） | 看收益差能不能把差额解释完 |
| `lcc_5ac` / `lcc_4ac` | 机队 6→5 / 6→4，**航线不变** | 审计没提，但成本拆解指向利用率 |
| `regional_base` | 支线（参照组，不是消融） | 被比较的对象本身要出现在同一张表里 |

## 4. 两条结论

### 4.1 两个系数确实分主次，但都不是根因

收益 +0.05 值 **+183 万**、供给 −0.10 值 **+79 万**，比例 **2.3 : 1** —— 主因是
`yieldMultiplier`。交互项 +4.0 万（单因子之和 262.6 vs 同调 266.6），可忽略。

**但两者同调也只有 −855 万，仍在 BANKRUPT。** 所以「调系数」这条路走到头也修不好这个组合。
这一点很重要：如果只做审计点名的两个消融，很容易得出「把 yield 调到 0.90 就好了」的错误结论 ——
那个结论在滞胀下**不成立**。

### 4.2 根因是机队利用率

成本拆解（滞胀，万美元/年）：

| 航司 | 燃油 | 起降+机组 | 机队维护 | 固定开销 | 人力 | 航权维持 | 碳 | 合计 |
|---|---|---|---|---|---|---|---|---|
| 低成本 | 1339 | 2426 | 381 | 240 | 1440 | 108 | 184 | 6117 |
| 支线 | 757 | 1645 | 210 | 240 | 720 | 101 | 102 | 3775 |

低成本多花 2342 万 = 随班次 +1362（燃油+起降机组）+ 随机队/规模 +898（维护+固定+人力+航权）。
营收只多 2027 万，所以净差 −315 万。

关键在最后这张表：

| 航司 | 周班 | 机数 | 每机每周班次 | 单位周班成本 | 单位周班营收 |
|---|---|---|---|---|---|
| 低成本 | 70 | 6 | **11.7** | 87.4 | 71.4 |
| 支线 | 56 | 3 | **18.7** | 67.4 | 53.0 |

飞机同样在折旧、在养机组（`HrEconomics.LaborCostPerAircraftWan` = 20 万/机/月，
低成本 1440 = 6×20×12，支线 720 = 3×20×12），飞得越少，单位班次背的固定负担越重。
减到 4 架（利用率 17.5 ≈ 支线 18.7）后净利 −507，**反超支线 −805**。

也就是说：**「低成本差过支线」这个异常，全部由两家的机队几何差异解释**，不是航线经济系数错了。

## 5. 结论的边界（必须一起读）

`AirlineYearSimulator` 的营收只由航线算、**不看机队**（没有运力约束），所以「减机」那两行
是**不付营收代价的上界**，不是可执行的机队方案。它们证明的是「固定负担/班次」这个机制的量级，
不是「换 4 架就能活」。

真正该改的是**压力测试夹具的机队与周班配比**（6 架配 70 周班 = 11.7 班/机/周，本身偏松），
不是航线经济系数。把这个前提固化成了闸门不变量 `fleet-only-no-revenue:lcc_5ac` /
`fleet-only-no-revenue:lcc_4ac`：一旦运力约束接进来，这两条会红，提醒后来者重推本节结论。

**没有动的**：`yieldMultiplier`、`CompetitorSupply`、任何系数、`BASELINE_SOURCE.json`。
矩阵 60 行数值零变化。

## 6. 闸门：`--ablate` 的两条不变量并入 `balance` profile

如果归因表只靠「我这一轮读数」，那它和之前那些「有过一次走查」没有区别。所以把归因成立的前提
变成机器断言，和现金桥进同一个计数：

| 断言 | 数量 | 失败意味着 |
|---|---|---|
| 现金桥残差 ≤ 0.5 万 | 60 | 现金流有未登记路径 |
| 各变体成本明细项之和 == 合计（±1 万） | 8 | 有成本塞进了 `TotalCostWan` 却没拆出来 |
| 纯减机变体营收 == 基准营收（逐位） | 2 | 运力约束接入了，§4.2 的归因需重推 |

```
$ dotnet run --project tools/balance --no-build -- --bridgecheck
现金桥检查：60/60 对账通过（容差 0.5 万，最大残差 0.03 万）
对照实验不变量：10/10 通过
{"assertionsTotal":70,"assertionsFailed":0,"assertionsSkipped":0,"bridgeTotal":60,"invariantTotal":10,
 "worstResidualWan":0.03,"toleranceWan":0.5}
exit=0
```

`balance` 的验收模板同步改成 4 条（现金桥 / 对照实验不变量 / 计数一致 / 快照完整），
`config.json` 与 `config.example.json` 的 profile 描述同步。

## 7. 一个顺手发现的口径缺口（未修，已记录）

`MonthlyPnL` **没有** `RouteFixedCostWan` 字段：航线周期固定成本在 `SimulateMonth` 里算出来、
计入了 `TotalCostWan`，但没有作为明细项返回。后果是「把月度明细项加起来」永远比 `TotalCostWan`
少这一笔，任何按 `MonthlyPnL` 逐项对账的人都会撞上。

本次的绕过方式是从 `YearSummary.RouteFixedCostWan`（年汇总，有该字段）取，并把
「明细项之和 vs 合计」做成断言 —— 现在七个变体全部在 ±0.08 万内（逐月 `Round2` 累计）。

**没有改 `MonthlyPnL`**：加字段会动 `SimModels` 的公共形状，牵动所有读月度明细的报告
（`--stress` 报告、`QuarterlyOneOffReport`、CSV 导出）。属独立改动，不在本次范围。
