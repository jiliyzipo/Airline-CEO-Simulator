## 3. 硬约束（违反即拒收，不要讨价还价）

1. **行为不变优先于一切性能收益。** 现有断言不得删除、不得放宽容差、不得改成 `Assert.Ignore`。
2. **存档兼容**：`GameState` / `InboxMail` / `RouteData` / `Aircraft` / `Loan` / `StrategyState` 等
   `[Serializable]` 类型的 **public 字段名不得重命名、不得删除、不得改类型**（`JsonUtility` 按字段名持久化）。
   确需废弃的字段保留并加注释，或写迁移；**任何此类改动必须附旧存档往返用例**。
3. **GUID 稳定**：不得删除 `.meta`、不得重新生成 guid、不得断开 `prefab` / `scene` 引用。
4. **数值不漂移**：改运算顺序导致浮点求和变化即视为行为变更。验收口径：
   `dotnet run --project tools/balance/AirlineCEO.Balance.csproj -c Release -- --bridgecheck`
   的 60 组合分布（GREEN/BANKRUPT/RED）必须完全相同，期末现金/净利差 ≤ 0.01 万；否则停下来问用户。
5. **不改经济与平衡参数**（`EconomyBalanceParams`、`OpsEconomics` 常数、难度表）。调参另有授权流程。
6. **不动基线机制**：`.gitattributes` 的 `* -text`、`clean-checkout-verify` 的逐字节口径、
   `docs/handoff/Baseline_*.json` 的指纹语义。
7. **不引第三方依赖、不升级 Unity 版本、不改 `ProjectSettings` 的渲染/图形管线**。
8. **不删测试、不跳过**：每批 `skipped` 必须为 0（`Explicit` 用例按需显式点名，不算 skipped）。
9. **单批规模**：一批 ≤ 25 个文件改动、≤ 1 个 DEL；超了就拆批。批与批之间必须全绿。
10. 不得顺带"美化"未触及的文件（禁止 drive-by reformat / 全文件换行符 / 批量重排 using）。

## 4. 四个阶段（按顺序，每阶段一批）

### Phase 0 · 体检报告（**不改一行代码**）

产出 `docs/handoff/Code_Health_Scan_2026-10-31.md`，必须用工具而不是肉眼，至少包含：

- 死代码：未引用类型/方法/字段清单（判定方法见 §5），标注「疑似 / 确认」。
- 重复实现：语义重复的函数族（同名或同形），给出合并候选与风险。
- 巨类拆解依赖图：`InboxManager`(6595 行)、`LogicSelfTests`(5555)、`CapacityDirectiveLogic`(2442)、
  `MapWidget`(2169)、`InboxPanelUI`(2037) —— 每个给出「按职责拆几块、边界在哪、跨调用点数量」。
- 热路径候选：每帧/每 tick 被调用的分配点（`new`、`string.Format`、LINQ、`GetComponent`、`Find*`）。
- Unity 导入开销：14 处 `[InitializeOnLoad]` / `AssetPostprocessor` 的逐个耗时估算
  （`RegressionTriggerBridge`、`WeatherTileDomainReload`、`DevelopmentPlaySmoke`、`SymbolFontImportSettings` 等）。
- 工具链开销：`delivery` 记录体积构成、`out/` 占用明细、`semcheck` 两个 85 KB 生成 csproj 的必要性。

**退出条件**：报告落地 + 用户/Cursor 确认范围。Phase 0 不计入"已改代码"。

### Phase 1 · 零风险清理（纯删除/收敛，不改逻辑）

候选（Phase 0 确认后执行）：

- 确认无引用的类型/方法/字段（含 `#if` 分支内、`MenuItem` 只被字符串引用的情况）。
- 注释掉的整段旧实现（保留了"历史对照"但已无价值的部分）。
- 未使用的 `using`、`Debug.Log` 洪泛（保留信息性日志，去掉逐帧日志）。
- 重复的工具函数合并到唯一实现（例如多份 `NumberAfter` / 格式化 / 时间圆整）。
- 不产生收益的空目录脚手架（`.gitkeep` 占位目录）—— 仅在确认无引用后删。

**禁止**在 Phase 1 顺手改任何判断条件、默认值、边界。

### Phase 2 · 结构减负（拆巨类、去重复）

- 先拆**最容易证明等价**的：纯静态工具类、无状态分支（如 `LogicSelfTests` 按套件拆文件、
  `DeptReportLogic` 的文本模板、`InboxManager` 的许可/时刻槽/回执三段）。
- 拆解方式优先 `partial` 或同程序集内新文件；**不新建 asmdef**（会改编译边界与 Unity 导入行为）。
- 每拆一块，跑一次全量回归；破坏公共 API 的拆解**不批准**。

### Phase 3 · 工程与工具链

- 交付快照不再复制 `Library/`（`snapshotRoots` / 排除规则），并提供 `prune` 类命令回收旧快照。
- delivery 记录的指纹去重/外置（同内容只存一次哈希，或按需引用 manifest），保证 `review` 仍能校验。
- `tools/balance` 的 csproj 改 glob 或由 `gen.js` 生成（现手工列 69 条 `Compile Include`，
  已因漏 `MapFlightState.cs` 挂过一次整条流水线）。
- 评估 `docs/` 里 96 个 PNG（565 MB，不含 `Assets/` 下的 5 张运行时图）是否必须进 Git；**不要擅自移出**，只出方案给用户裁决。
  **2026-10-31 实测结论（Cursor）**：96 张全部唯一、无重复；68 张部门经理立绘被 `docs/GameDesignBible/` 正文按角色名引用，
  17 张董事会立绘与 10 张 UI 稿无任何文字引用。Unity 工程内**没有任何立绘资源**（`Assets/` 下仅 7 张运行时图共 ≈7.9 MB），

## 6. 明确禁止的"优化"

- 不为微秒级收益引入 `unsafe` / `Span` / 自写容器。
- 不把同步方法改 `async`（Unity 主线程语义会被改坏）。
- 不合并 UI 面板、不改交互流程、不改文案 —— 那是产品改动，另走裁决。
- 不改浮点累加顺序、不把 `float` 换 `double`、不做"等价化简"（乘除结合律在浮点下不等价）。
- 不为降行数把代码压成一行、不删注释里的**事故说明**（本项目注释承载了大量"为什么不能这么写"，
  删了等于把踩过的坑留给下一个人）。
- 不"顺手"修 bug（见 §8）。

## 10. "完成"的定义

三个目标各自的数字都达标 + 每一批都有独立检测记录（Cursor）+ 用户对 Phase 2/3 的每一项改动知情。
**少任何一条都不算完成**：不接受"整体看起来更快了"，也不接受"测试没红所以没改变行为"——
本项目要求的是**行为逐项可解释**，不是"没报错"。
