# 阶段记录 · 时刻二级市场「可售判定」与「租一季」（2026-11-05）

> 触发：用户提问——「时刻二级市场页，除了他航待售时刻，是否需要添加『我司可售时刻』？
> 如何判断哪些时刻是可售，需要订规则。请从现实航司和时刻交易分析。」
> 三项裁定：① 升级现有右栏（不新增栏目）；② 只上**四条硬闸**；③ **加「租一季」**。

---

## 1. 现实依据（规则为什么这么定）

- **时刻不是产权**，是航季内的使用许可（IATA WASG），交易需协调人同意；禁止卖给非承运人。
- **80/20 + 祖父条款**：飞满 80% 才有下季自动保留，否则收回协调池 —— 闲置槽是有保质期的资产。
- **四种处置方式**：卖断（transfer，永久失去祖父条款）／置换（exchange）／**租一季**（lease，
  季末收回、保留历史优先权）／退回协调池。原实现只有「卖断」。
- 现实里航司**更常租不常卖**：卖断丢权，租一季只让出一个航季。故本轮补齐。
- 卖槽前必须先停飞/减班腾出来 —— 在飞的槽卖不掉。

## 2. 改动清单

### 2.1 可售判定（`Logic/SlotMarketLogic.cs`）

新增 `SaleState` / `SaleVerdict` / `EvaluateSale(gs, holdingIndex)`，口径集中一处：

| 顺序 | 状态 | 判据 | 标签 |
|---|---|---|---|
| 1 | `InUse` | `inUse == true` | 在飞·不可售（需先调开班次） |
| 2 | `Listed` | 已在我司挂牌中 | 已挂牌 |
| 3 | `Expired` | `expiresTurn >= 0 && <= 当前 turn` | 已过期（权利灭失） |
| 4 | `Leased` | `leasedUntilTurn > 当前 turn` | 出租中（季末收回） |
| 5 | `Reserved` | `usedByRouteId` 非空但未投运 | 在办预留（卖了会打回缺槽） |
| 6 | `Sellable` | 以上皆否 | 可售 |

- `ListOwn` 改为走 `EvaluateSale`，删除原先散落的 inUse/重复挂牌判断（避免两套判据打架）。
- `AcceptOffer` 过户前复用同一判定（挂牌期间可能被绑班、出租、过期）。
- `AutoListIdleSlots` 因此自动跳过不可售项。

### 3.1 回归过程中暴露并修掉的两个真实缺陷

1. **「在办预留」用 `usedByRouteId` 非空判定会误杀。** 首轮 `R47 ⑦b` 直接红：
   运营部代挂牌挂出 0 条 —— 持仓上残留的 routeId 让一条干净的闲置槽被判成「在办预留」。
   改为**必须有在办准入许可为证**（`RoutePermitLogic.InFlightPermits` + `InboxManager.RouteIdOf`
   对上这条航线），陈旧绑定不再拦；用例同时断言「陈旧绑定 → 仍可售」。
2. **挂牌时刻被 `NearestSeries` 吸附后，严格字符串比对找不到原持仓。** 首轮 `R47 ⑩`
   挂牌成功后立刻被判「已挂牌=False」，租一季也报「已不在持仓里」—— 因为 `ListOwn` 存的是
   吸附后的时钟，而 `HoldingIndexOf` 拿原时刻做精确比对，`PruneExpired` 随即把挂牌当孤儿剪掉。
   两处 `HoldingIndexOf`（含 listing 重载）统一改用 `ClockDiff ≤ SlotToleranceMinutes` 容差口径。

> 这两个缺陷都属于「页面说可售、实际挂了就被剪」这一类静默错误；若不做隔离回归，实机上只会表现为
> 「明明有闲置槽却没有挂牌 / 挂上去一会儿就没了」，很难定位。
