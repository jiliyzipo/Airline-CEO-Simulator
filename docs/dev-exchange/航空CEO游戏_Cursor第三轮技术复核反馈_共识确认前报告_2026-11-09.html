02 / SAVE COMPATIBILITY

争议一：B方案是否必然导致旧存档超配？

Cursor 的论点

Cursor 报告指出，部分24小时非宵禁机场的旧早班池从40个15分钟刻缩为16刻，例如 ORD 的池容量由320变为128，并以“旧早班持仓200条”为例认为会超配72条；进而称老存档必然超配。

复核意见：示例缺少持仓时刻分布，不能推出“必然”

按照 Cursor 自己描述的 SlotHolding 结构，持仓含机场、具体 slotTime 与起降方向；band 是根据时刻计算的。在 B 布局下，00:00–05:45 的持仓也会从早班池转入夜班池。

区间旧归属新归属ORD 假设每刻容量8时的区间容量
00:00–05:45（24刻）早班夜班192
06:00–09:45（16刻）早班早班128
旧早班合计40刻拆分为两池320

若旧早班200条持仓中，凌晨120条、06:00以后80条，新早班就只有80/128，并不超配；凌晨120条进入夜班。在每刻容量判据始终有效且所有持仓合法的前提下，单纯改变班次归属并不必然导致新早班超配。

仍然存在真实风险：旧版若有池级持仓未能映射到合法的逐刻记录、背景航司重新铺排占据了玩家持仓、历史档已含异常数据，或者分方向容量调整，仍可能出现超配。不能据此认定“肯定没风险”。

需要 Cursor 提交的证据

  1. 以真实或合法构造的持仓，逐刻列出旧/新 capacity、玩家持仓、背景航司持仓与新旧 band 归属。
  2. 对所有103座协调机场做可重复的旧档兼容模拟，指出实际出现超配的机场数、时刻数、来源与原因，不能只对池容量作直接比较。
  3. 分别评估：不重铺背景航司、按原算法重铺、玩家持仓优先保留三种情况。
  4. 明确超配告警及 Legacy 安全回退；在结果明确前不选择“强制退槽”“宽限期”或“自动删除”等产品处置。
03 / ECONOMIC RISK

争议二：全天余量大致不变，不等于经济平衡不变

Cursor 的离线模拟显示，B方案主要改变时刻剩余量的时间分布，而非全天总量。例如当前跑道容量＋真实哈希占用情景，06:00有余量的协调机场由22座变成102座；在 D16×固定75% 的81场样本中，08:00有余量的机场数为56→56，全天余量为9,800→9,800（单方向）。

同意的部分：B不等于扩大世界总容量，而是对既有可申请资源进行重新分布。
不同意的推断：总余量接近不变，不能证明航线经营、收益、机队利用率、董事会业绩或二级市场不受影响。

将“隐蔽在凌晨的余量”移向正常营业时段，可能让玩家开通此前无法排出的航线、提高周班次、减少对二级市场的依赖；客流收入与航班收益也可能因此改变。必须单独进行固定种子与固定资金的经营模拟。

05 / UNLIMITED AIRPORT EXTENSION

机场不设数量上限：接受诊断，但实施必须渐进

接受 Cursor 的判断：现有代码没有直接把81/103/104写成机场数量上限，却存在 IATA 单一主键、静态只读机场数组、int[4] 烘焙容量、缺少机场自身时区及线性查找等扩展障碍。这些都值得进入架构改造规划，但不代表当前必须推翻四张机场表。

现有风险长期架构目标当前阶段
IATA作为唯一关联键稳定内部 airportId；IATA/ICAO分别作为可选外部标识并建立索引。提交旧档映射策略与冲突检查。
机场只在静态数组注册支持从数据源加载新增机场，未来玩家可搜索所在地附近真实机场并启用。先定义注册接口与数据完整性校验。
容量在启动时固定烘焙由单一 CapacityService 根据机场数据、航季和已生效事件计算容量；衍生缓存可失效重建。提供兼容现有int[4]读接口的迁移设计。
缺少机场当地时区为机场建立 IANA 或等价可靠时区标识，明确 UTC↔当地时间与夏令时策略。先审计当前时间语义及对跨午夜的影响。

缺少跑道/申报容量的记录缺失和估算值必须明确可诊断；协调与非协调机场使用各自适用的资源规则。对现有104座机场提供完整性清单。
