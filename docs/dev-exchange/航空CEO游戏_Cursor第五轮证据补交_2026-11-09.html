04 / FIXTURE SCOPE

「3,116 条」的正确命名与边界

原报告称「A 布局下的最大合法持仓」。准确说法是：在初始背景占用不变的前提下，把每一刻的免费余量全部取满。它不含二级市场成交、不含后期经营演化、不含按航线需求形成的非均匀分布，因此不是「所有合法存档的上界」。

06 / NEW DEFECT

新发现：B 夜班数组的下标接缝（可复现）

评审要求「先给失败案例，再决定是否改结构」。以下是可复现的失败案例，触发条件明确。

机理

B 布局的夜班池覆盖 20:00→次日 05:45，但 BandGrid 按分钟升序生成，于是数组是 [00:00 … 05:45, 20:00 … 23:45]。Place 以「下标 ±d」找空刻：

// IndustryAirlineLogic.Place 第 977–987 行
for (int d = 0; d < n; d++) {
    int a = target - d, b = target + d;
    if (a >= 0 && a < n && perQ[a].Count < capAt[a]) { perQ[a].Add(name); return true; }
    if (b >= 0 && b < n && b != a && perQ[b].Count < capAt[b]) { perQ[b].Add(name); return true; }
}

d = 1 时同时探测 target−1 与 target+1，且 a 优先。夜班数组下标 23 → 24 正是 05:45 → 20:00，下标相邻、实际相差 585 分钟。

复现（同一持仓、同一填充状态，仅班次归属不同）

布局05:45 所在池05:30 / 05:45 已满探测顺序落位位移
A（早班 00:00–09:45 连续）早班，40 刻是d0 下标23 满 → d1 a=22 满 → d1 b=24（06:00）空06:00+15 分
B（夜班 00:00–05:45 ＋ 20:00–23:45）夜班，40 刻是d0 下标23 满 → d1 a=22 满 → d1 b=24（20:00）空20:00+585 分
触发条件（必须说清，避免夸大）：① 接缝两侧至少有一刻逐刻超容。合法存档在 A/B 之间迁移不会产生逐刻超容（§04 三重计数：丢弃 0、位移 0），所以本缺陷不是 B 迁移的必然结果；② 可达路径是「同一刻被多条离网格持仓吸附后超容」（NearestGridIndex 把 ±7 分内的持仓都映射到同一刻），或「早于 f41de9d 容量重解、逐刻容量更高的历史档」。因此这是条件缺陷，不是确定性缺陷。

修复代价极低，且与是否采纳 B 无关：把夜班网格按「日序」排序（20:00 … 23:45 → 00:00 … 05:45），使下标相邻 = 时间相邻；或让 Place 以时刻距离而非下标距离选候选。两者都不改存档、不改容量。建议连同 BandHourStart/End 的跨午夜返回类型一起，作为 B 落地的前置小修，纳入 P1 第一项。

脚本：out/analysis/seam-case.mjs、out/analysis/place-consistency.mjs；输出 out/analysis/seam-case.json、place-consistency.json。
