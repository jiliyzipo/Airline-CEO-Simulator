## 三、明确选择：补隔离 EditMode，再补本批真实申请序列

选择 Cursor 推荐的 B。补测属于已经确认的首批验证，不另开新功能任务，不必再让用户选择技术路线。

### 1. 隔离 Unity EditMode

- 使用项目既有隔离导出及测试入口，固定导出来源与版本；测试前后保持主工程及玩家数据不变。
- 隔离副本正确配置 companyName 等数据隔离设置；不得直接修改主工程身份来绕过隔离要求。
- 运行 CapacityServiceEditModeTests.ExtractionPreservesEveryCapacityCell 及覆盖实际程序集依赖的必要编译/测试；不调用完整 LogicSelfTests.Run() 代替隔离回归。
- 检查 Runtime、Editor 与测试程序集真实引用、静态初始化、缓存和测试发现。记录实际发现/执行的测试数、断言结果和日志/XML 路径；零测试不得算通过。
- 先检查 Unity 占用。无占用则按既有权限执行；有真实占用则不杀进程、不删锁，说明需要用户保存关闭的编辑器及原因。环境无法运行记为未覆盖，不能伪造通过。

### 2. 完整申请序列仍属于首批

前述共识已经要求相同初始状态、相同操作序列下的批准/拒绝、持仓与资金变化全等。不能以“判据层全等”删除这一条件，也不必另立一轮产品设计讨论。

- 首先使用可覆盖真实调用链的最小 C# 测试入口；能在 EditMode 完成就不扩大到完整 PlayMode。确实依赖游戏循环的步骤，再使用定向 PlayMode；不是完整经营 A/B。
- 固定抽取前实现或可追溯的旧版本快照，不用新实现重生成基线并以此自证。相同初始状态、游戏时间、随机条件和输入序列分别在前后版本执行。
- 至少覆盖合法申请、满刻/满池拒绝、DEP/ARR 配对与资金不足/重复操作等与实际入口有关的场景；执行现有申请、交割/成交及必要结算逻辑，比较批准/拒绝原因、持仓时刻/方向/数量、资金流水和余额。
- 同时核对背景占用与申请余量，保持 kind 返回值、布局、跑道口径和存档写出不变。若已有测试覆盖，复用并提交覆盖映射，不重复堆同义测试。
- 发现范围内回归可修正、自测并记录；涉及改规则、改存档或扩大实现范围，先反馈 Codex，不自行修成另一种玩法。
